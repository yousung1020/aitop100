# 운영 및 테스트 검증 계획

갱신일: 2026-10-31. 이 문서는 준비 계획이며 배포 완료 보고서가 아닙니다. Unit 5 하네스·평가 결과와 Unit 6 운영 채널 검증 기록은 아직 없습니다. 현재 목표는 [HANDOFF.md](../HANDOFF.md)의 Unit 5 기대 동작·하네스 작성이며, Unit 3·4 잔여 결함은 [공식 API 재확인 기록](API_CONSISTENCY_AUDIT.md)에 명시합니다.

## 1. 배포 전 확인 사항

호스팅·고정 도메인·터널 중 어떤 인프라를 사용할지는 사용자 확인 후 결정합니다. 문서의 예시 도메인은 실제 발급·소유·배포를 뜻하지 않습니다. 제출 시각·심사 기간·변경 금지 범위는 참가자 안내 원문을 다시 확인합니다. 과거의 “32시간 운영”, “15시 이후 모든 변경 금지”를 확인된 규정으로 사용하지 않습니다.

카카오 채널과 오픈빌더 설정 시 채널 공개·검색 설정의 대회 요구사항을 확인하고, 스킬에 실제 HTTPS URL의 `/skill`을 연결합니다. `/skill/cs`와 `/api/kakao/chat`도 구현되어 있습니다. 블록이 스킬 응답을 사용하도록 연결한 뒤 테스트 채널과 운영 배포 양쪽에서 SimpleText 하나만 출력되는지 확인합니다. 이 체크리스트를 작성한 것만으로 콘솔 설정 완료로 처리하지 않습니다.

## 2. 로컬 기동 및 외부 연결

기존 가상환경에서 로컬 기동을 확인하는 명령입니다.

```bash
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
curl -fsS http://localhost:8000/health
```

`/health` 성공은 프로세스 기동 확인이며 Gemini·공식 업무 API 정상 동작을 증명하지 않습니다. 실제 키·토큰은 `.env`에만 설정합니다. 운영 설정과 모델 선택은 [README](../README.md)를 참조합니다.

Cloudflare Quick Tunnel을 선택한 개발 테스트의 예시는 다음과 같습니다. 이 명령을 문서 갱신 과정에서 실행하지 않았습니다.

```bash
cloudflared tunnel --url http://localhost:8000
```

Quick Tunnel은 임의의 `trycloudflare.com` 주소를 발급하며 가동 시간 보장이 없는 개발·테스트 용도입니다. 고정 주소가 필요하면 계정·도메인 조건을 확인하여 Named Tunnel 또는 다른 호스팅을 검토합니다. 특정 방식을 대회 필수 조건으로 단정하거나 터널 연결이 끊기지 않는다고 보장하지 않습니다. [Cloudflare 공식 안내](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)를 참조합니다.

## 3. 현재 검증 결과와 Unit 5 완료 기준

수정 후 로컬 재실행은 **229 passed in 5.02s**입니다. 이전의 `220 passed` 및 `13 failed, 207 passed`는 수정 전 이력입니다. 현재 테스트는 기존 Mock 계약과 출력·정책 테스트를 포함하며 공식 서버·실제 모델·공개 TC 전수 통과 결과가 아닙니다. 별도 탐침에서 공식 접수 계약과 공개 TC 흐름의 잔여 결함이 확인되었습니다. 이전의 11개 질문 예시는 30건 하네스가 아니므로 제거했습니다. `tests/simulate_30_cases.py` 및 평가 결과는 아직 없습니다.

Unit 3·4 보완 후 Unit 5에서는 [공개 TC 15건](PUBLIC_TEST_CASES.md)을 기준으로 다음 항목을 검증합니다. 자체 30건 확장 계획은 공식 공개 목록과 구분합니다.

- 단일 질문뿐 아니라 주문 확인·고객 선택·후속 발화가 포함된 대화를 재현합니다.
- TC ID·상담일·인입 계정·주문/결제/배송/로트 식별자와 실제 API 호출 순서·본문을 검사합니다.
- 가능 여부 문의의 성급한 변경, 타인 정보 공개, 불필요한 환불·쿠폰 발급 등 금지 동작을 검사합니다.
- SimpleText 1개·500자 이하·공백 답변 없음과 오류·타임아웃 시 안내를 검사합니다.
- POST 접수를 실제 변경·환불·발행 완료로 표현하지 않는지 검사합니다.
- 로컬 결정적 계약 검증과 실제 모델·실서버 검증을 구분해 건수·실패 원인·실행 환경을 남깁니다.
- 실제 채널 지연·p95·글자 수·말풍선 수를 측정하고 목표 초과를 실패로 기록합니다. 결과 집계만으로 ALL PASS를 출력하지 않습니다.

업무 API 연습은 참가자 데이터가 TC 간 공유되고 접수 이력이 남습니다. 공개 TC ID·연습 가능 기간·호출 한도를 확인하며, 데이터 초기화는 별도 범위를 확인한 뒤 실행합니다. 문서 수집·이번 정합성 수정에서는 실제 업무 접수와 초기화를 실행하지 않았습니다.

## 4. 운영 검증 계획

인프라가 정해진 뒤 서버·외부 URL·채널·모델·액션 서버를 각각 검증합니다. 프로세스 종료·기기 절전·네트워크 변경·터널 재연결에 따른 영향을 점검하고, 선택한 환경에 맞는 프로세스 관리와 상태 확인을 구성합니다. 웹훅 내부 제한 4.5초는 액션 클라이언트 자체 제한이나 전체 채널 실측 지연과 구분합니다.

접근·오류 로그에서 모델 실패·액션 실패·타임아웃을 확인하되 키·토큰·고객 개인정보는 기록하지 않습니다. 최종 제출 URL과 운영 기간, 변경 허용 범위는 공식 참가 안내로 확정한 후 인계 문서에 반영합니다.
