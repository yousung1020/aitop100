# 공식 API 문서 정합성 재확인

확인일: 2026-10-31 13:41 KST. 로그인된 실제 Chrome의 [공식 액션 API 페이지](https://aitop100.org/contest/docs#description/introduction)를 읽고, 같은 브라우저 세션에서 문서 리소스 `GET /api/contest/docs/actions`를 HTTP 200으로 조회했습니다. 업무 API·접수·초기화는 실행하지 않았습니다. 인증값·쿠키는 수집하지 않았습니다.

## 2. 다시 확인한 공통 계약

- 접수는 요청 기록이며 정책을 판정하거나 주문·결제의 상태·금액을 변경하지 않습니다. 주소 변경 반영 완료를 보장할 근거도 아닙니다.
- 같은 접수 API·같은 대상은 본문을 바꾸어도 같은 접수번호를 반환하고 마지막 본문으로 접수 내용을 갱신합니다. 대상이 없는 이관은 본문으로 접수번호를 정합니다.
- 단건 부재·미등록 경로/메서드는 빈 본문 404입니다. TC 헤더 오류를 제외한 규격 위반 400도 빈 본문입니다.
- 업무 API에는 실제 대화의 TC ID를 유지해야 합니다. 평가 전에는 공개 TC ID만 허용하며 `TC-DEFAULT`가 허용된다고 볼 근거는 없습니다.
- 시간 창 한도는 60초당 100회, 평가 누적 한도는 3,000회입니다. 누적 한도는 기다려도 복구되지 않습니다.
- 초기화는 TC 헤더·본문 없이 성공 204이며, 최종 제출 후 또는 평가 시작 시각부터 금지됩니다.

아래는 공식 원문 변경이 아니라 앞선 로컬 코드 검토·재현 결과입니다. 전체 pytest는 **229 passed in 5.02s**였지만 공개 TC 전수 통과를 뜻하지 않습니다.

| 완료 보고의 표현 | 확인된 제한 |
| :--- | :--- |
| Unit 3·4 P1 전면 해결 | 공식 접수 규칙·실제 대화 처리에 아래 결함이 남아 있어 완료 확정 불가 |
| Mock 공식 스키마 지원 완료 | 주소 접수에서 원본 주소를 즉시 바꾸고, 같은 대상 재접수에 다른 접수번호를 반환. 배송 Mock도 공식 필수 필드가 누락되고 공식 enum에 없는 `SHIPPED`를 사용 |
| 공개 TC 필수 API 완비 | API-25·27은 클라이언트에 없으며, 현금영수증·환불·쿠폰·재배송 메서드가 있어도 오케스트레이터에 해당 처리 분기가 연결되지 않음 |

| 안전한 주소 변경 처리 | 배송 조회 실패를 빈 검색 결과와 같이 취급하여 API-24를 접수하는 동작을 로컬 재현 |
| 상담 문맥 연동 완료 | 상담일·인입 계정·히스토리 저장은 존재하지만 실제 판단 및 모델 입력 연결은 미완료 |

공개 TC 로컬 탐침에서는 L-05에 주문번호·발행 구분을 추가해도 호출이 없었고, L-47도 호출이 없었습니다. L-23은 기대되는 계정 귀속 조회·이관 대신 배송 검색을 실행했습니다. 이는 해당 상담의 기대 흐름과 맞지 않으며, 정식 15건 하네스 실행 결과로 집계하지 않습니다.

## 4. 검증 범위와 다음 작업

이번 Chrome 재확인은 액션 API 문서에 한정합니다. 공개 TC 15건의 원문·첨부 사진·음성을 새로 수집하거나 검증한 것은 아닙니다. 카카오 인입 메타데이터의 정확한 전달 위치, 대회 일정·배점·실격 기준도 이 액션 API 문서만으로 확정하지 않습니다. SimpleText 하나·500자 상한·내부 4.5초는 AGENTS의 프로젝트 제약으로 유지합니다.

Unit 5의 기대 호출·금지 액션 데이터 및 하네스 작성은 진행할 수 있습니다. 현 구현의 실패를 그대로 기록해 Unit 3·4 보완에 사용하고, 위 결함을 남긴 채 구현 완료나 공개 TC 통과로 보고하지 않습니다.
